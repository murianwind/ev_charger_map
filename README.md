# 전국 테슬라 충전 지도

한국환경공단 `EvCharger` API + 테슬라 슈퍼차저 커뮤니티 데이터(`supercharge.info`)를
합쳐서, 이용제한 없는 완속충전기(AC완속/NACS/DC콤보+NACS)와 슈퍼차저를
GitHub Pages 지도(`docs/index.html`)에 표시합니다.

## 코드 구조

역할별로 모듈을 나눴습니다 (하나의 파일이 여러 역할을 겸하지 않도록).

```
scripts/
├── kst_time.py          # 공통 유틸: 한국 표준시(KST) 계산
├── http_client.py       # 범용 HTTP 계층: curl 호출, 재시도, 한도초과 감지, 시크릿 마스킹
├── quota_cooldown.py    # 일일 호출 한도 초과 시 다음날까지 재시도를 쉬는 쿨다운 상태 관리
├── address_parser.py    # 한글 주소 텍스트 파싱(주소+시설명 분리) 및 좌표 대략 검증
├── kakao_geocoder.py    # 카카오 로컬 API로 좌표 검증/보정, 역지오코딩, 장소명 검색 (선택 사항)
├── gov_charger_api.py   # 환경공단 API 전용: 페이지네이션, 필터, 지역(zcode) 요일별 그룹
├── tesla_source.py      # supercharge.info 전용: 테슬라 슈퍼차저 조회
├── tesla_snapshot.py    # data/tesla_snapshot.json(마지막 성공 슈퍼차저 목록) 읽기/쓰기
├── geojson_store.py     # chargers.geojson 읽기/쓰기, 지역별 부분 교체 병합, 재시도 대기 기록
├── fetch_chargers.py    # 일일 진입점 — 담당 지역(+재시도 대기 지역) 갱신, 슈퍼차저 스냅샷 반영
├── fetch_status.py      # 델타 진입점 — 최근 상태 변경분만 갱신
├── fetch_tesla.py       # 슈퍼차저 진입점 — supercharge.info 조회 후 스냅샷 갱신
└── commit_and_push.sh   # 워크플로 공용 — 커밋/푸시, push 거부 시 rebase 재시도
tests/
├── features/*.feature   # BDD 시나리오 (한글 Gherkin)
└── conftest.py          # 스텝 정의 (네트워크는 전부 가짜로 대체)
```

테스트 실행: `pip install -r requirements-dev.txt && python -m pytest tests`

각 모듈은 자신의 계층만 안다는 원칙을 지켰습니다: `http_client`는 EV 충전소를
모르고, `gov_charger_api`는 GeoJSON을 모르고, `geojson_store`는 API를 모릅니다.

## 필터 조건

| 조건 | 값 |
|---|---|
| 이용자 제한 | `limitYn == "N"` (제한 없음) |
| 주차료 | `parkingFree == "Y"` (무료) |
| 충전기 타입 | `chgerType`가 `02`(AC완속) / `09`(NACS) / `10`(DC콤보+NACS) |
| 삭제 여부 | `delYn != "Y"` |
| 시설 구분 | 아래 표 참고 — 20개 카테고리 제외 |
| 텍스트 필터 | `limitDetail`/`useTime`에 "비개방"/"불가"/"금지"/"외부인"/"입주민"/"거주자"/"제한될 수" 포함 시 제외 |

`limitYn=N`이어도 `limitDetail`에 텍스트가 남아있는 경우, 팝업 하단에 "참고"
메모로 노출됩니다 (실제로 이 필드 덕분에 위 텍스트 필터 조건들을 찾아냈습니다).

## 좌표 정확도 검증 (카카오 지오코딩)

환경공단 API는 위/경도 값 자체가 틀린 경우가 있습니다 (예: 주소는 대전인데
좌표는 이천 근방). 매일 갱신하는 지역이 전국이 아니라 하루치 분량(몇백~천
개소 수준)이라, 충전소마다 카카오 로컬 API(주소 검색)로 지오코딩해서
검증해도 무료 한도(하루 30만 건)에 전혀 부담이 없습니다.

- **`KAKAO_REST_API_KEY`** 시크릿이 설정돼 있으면: 주소로 지오코딩한 좌표와
  원본 좌표를 비교해 3km 넘게 차이나면 지오코딩 좌표로 교체합니다.
- **설정 안 돼 있으면**: 지오코딩을 건너뛰고, 기존의 대략적인 도(道) 사각형
  범위 검증(`coordinates_plausible`)만 적용합니다 — 완전히 다른 도시로 튄
  경우는 잡지만, 같은 시/도 안에서의 미세한 좌표 오차는 못 잡습니다.

**설정 방법**: [Kakao Developers](https://developers.kakao.com)에서 앱 생성 →
"카카오맵" 또는 "로컬" API 사용 동의 → REST API 키 발급 → 저장소
Settings → Secrets → `KAKAO_REST_API_KEY`로 등록.

## API 호출 부담 설계

data.go.kr 개발계정은 **하루 1,000건** 호출 제한이 있습니다. 전국을 매번 통째로
스캔하면 이 한도를 계속 위태롭게 넘나들게 되어, 두 가지로 나눴습니다.

**1) 지역 7일 로테이션 (`fetch_chargers.py`, 매일 04:00 KST)**

가이드 문서의 공식 `zcode`(시도 코드) 16개를 요일별로 나눠, 하루에 그날 담당
지역만 다시 받아옵니다. 일주일이면 전국이 한 바퀴 갱신됩니다.

| 요일 | 지역 |
|---|---|
| 월 | 경기(41), 충남(44), 제주(50) |
| 화 | 서울(11), 전남광주통합(12), 세종(36) |
| 수 | 부산(26), 대전(30) |
| 목 | 경남(48), 충북(43) |
| 금 | 인천(28), 강원(51) |
| 토 | 경북(47), 전북(52) |
| 일 | 대구(27), 울산(31) |

큰 지역과 작은 지역을 섞어 하루 부담을 비슷하게 맞췄습니다 (`scripts/gov_charger_api.py`의
`DAY_ZCODE_GROUPS`만 고치면 재조정 가능). 처음 배포하거나 데이터를 통째로
다시 채우고 싶을 땐 `FULL_SEED=1` 환경변수로 실행하면 전체 지역을 한 번에
갱신합니다 (GitHub Actions에서 수동 실행 시 체크박스로도 선택 가능 — 평소
자동 실행에는 쓰지 않습니다).

**지역 갱신 실패와 재시도**

정부 API는 간헐적으로 "정상 JSON인데 내용이 비어 있는" 응답을 줍니다. 지역
갱신은 `totalCount`만큼 끝까지 받은 지역만 교체하고, 비었거나 중간에 끊긴
지역은 기존 데이터를 그대로 둔 채 `meta.pendingRegions`(재시도 대기)에
기록합니다. 실패한 지역이 하나라도 있으면 그 실행은 **빨간색(실패)**으로
끝납니다(성공한 지역과 대기 기록은 커밋됨).

대기 지역은 홈 스케줄러가 04:35~09:35 KST 매시 35분에 dispatch하는 재시도
실행(`retry_pending`)이 다시 받습니다 — 대기 지역이 없으면 API를 호출하지
않고 바로 끝납니다. 그래도 못 받은 지역은 다음 날 정기 실행이 함께 받습니다.

**2) 상태 델타 갱신 (`fetch_status.py`, 10분마다)**

`getChargerStatus`는 `period`(분) 파라미터로 그 시간 안에 상태가 바뀐 충전기만
돌려주는 델타 피드라서, 전체를 다시 받지 않고 변경분만 기존
`chargers.geojson`에 병합합니다.

두 작업을 합쳐도 하루 약 400~500회 수준이라 한도에 여유가 있습니다.

## 실행 환경

두 스케줄이 실제로 도는 곳은 **오드로이드(홈서버)의 Docker 컨테이너**입니다
(`combined-stack/`). data.go.kr API가 해외/클라우드 IP를 차단하는 것으로
확인돼서, GitHub Actions의 클라우드 러너 대신 집 IP에서 도는 self-hosted
러너를 씁니다.

컨테이너 하나가 두 역할을 겸하는데, **실제 작업(스크립트 실행, git
커밋/푸시)은 이 컨테이너가 직접 하지 않습니다.** 대신:

1. 컨테이너 안의 **리눅스 cron**이 정해진 시각에 GitHub API로
   `workflow_dispatch` 이벤트만 쏩니다 (`trigger_workflow.sh`).
2. 같은 컨테이너에 등록돼 있는 **GitHub Actions self-hosted 러너**가 그
   요청을 받아서 실제 작업(파이썬 스크립트 실행 + git commit/push)을
   수행합니다.

이렇게 하면 cron이 트리거한 실행이든, GitHub 웹에서 "Run workflow"로 수동
실행한 것이든 **전부 GitHub Actions 탭에 동일하게 실행 기록(로그, 성공/실패,
소요시간)이 남습니다.** 컨테이너 자체는 git을 몰라도 되고, 잠금(`flock`) 같은
것도 필요 없습니다 — 러너 하나가 잡을 순서대로 처리해주기 때문입니다.

**경합 방지**: 두 워크플로 모두 dispatch 시점이 아니라 실행 시작 시점의
`main` 최신 커밋을 체크아웃합니다(같은 시각에 dispatch된 다른 실행이 먼저
push해도 그 위에서 출발). 그래도 push가 거부되면 `commit_and_push.sh`가
rebase로 다시 시도하고, 같은 파일이 충돌할 때만 스크립트를 처음부터 다시
돌립니다.

**테슬라 슈퍼차저만 예외**로 GitHub 호스팅 러너에서 돕니다
(`update-tesla.yml`, 매일 03:17 KST). supercharge.info는 응답이 몇 분씩
걸리거나 아예 안 올 때가 있는데, 하나뿐인 집 러너가 그동안 묶이면 10분 주기
상태 갱신이 밀리기 때문입니다. 이 워크플로는 `data/tesla_snapshot.json`만
갱신하고, 지역 갱신이 그 스냅샷을 지도에 합칩니다. 조회에 실패하면
스냅샷(=지도의 슈퍼차저)은 마지막 성공분 그대로 남습니다.

`combined-stack/`의 파일(crontab, 스크립트)을 고치면 Portainer에서 스택을
다시 빌드·배포해야 적용됩니다.

설정 방법은 `combined-stack/` 안의 파일들과 Portainer "Repository" 스택 배포
방식을 참고하세요 (Dockerfile이 저장소에 같이 있어야 GUI만으로 빌드 가능).

## 실행 상태 확인

- **GitHub Actions 탭**: 모든 실행(cron/수동 불문)이 여기 남습니다.
- **지도 페이지 헤더**: "지역갱신 MM/DD HH:MM · 상태갱신 MM/DD HH:MM"으로
  마지막 갱신 시각이 표시됩니다. 한도초과로 건너뛴 경우 "(한도초과로 건너뜀)",
  일부 지역이 실패한 경우 "(일부 지역 실패 — 재시도 대기)"가 같이 표시됩니다.
- **API 일일 한도 초과 시**: 자동으로 다음날 자정(KST)까지 재시도를 쉬고,
  그동안 들어오는 실행 요청은 API를 아예 호출하지 않고 즉시 건너뜁니다
  (`gov_charger_api`의 쿨다운 로직).

## API 호출 주기에 대한 참고

`getChargerStatus`의 `period` 파라미터는 **문서 기준 1~10분까지만
유효**합니다(기본값 5). 그래서 상태 갱신은 반드시 10분 이내 주기로 돌아야
하고, 이 델타 엔드포인트는 지역별로 나눠서 뜸하게 도는 방식이 안 맞습니다
(한 지역을 10분보다 뜸하게 보면 그 사이 변경분을 놓치게 됩니다). 지역
로테이션(7일 분산)은 `getChargerInfo`(위치/이용조건 등 정적 정보) 쪽에만
적용되고, 상태 델타는 전체를 자주(10분 이내) 보는 지금 방식이 이 API 제약
안에서는 최선입니다.

## 지도 동작

- 접속 시 위치 권한을 요청해 현재 위치로 이동, "현재 위치로 이동" 버튼으로
  언제든 복귀 가능
- **현재 화면(뷰포트)에 보이는 마커만** 그립니다 (전체를 한 번에 그리면
  마커가 너무 많아 성능 문제가 생겨서, 화면 밖은 그리지 않는 방식으로 변경).
  줌인할수록 자동으로 마커 수가 줄어듭니다. 한 화면에 1,500개 넘게 잡히면
  더 확대하라는 안내만 뜹니다.
- 헤더의 AC완속/NACS/DC콤보+NACS/수퍼차저를 클릭하면 해당 타입만 걸러
  볼 수 있습니다 (여러 개 선택 시 합집합 — 선택한 것 중 하나라도 해당하면 표시).
- 테슬라 슈퍼차저는 빨간 테두리로 구분되고, 팝업엔 개별 커넥터 상태 대신
  "충전기 N개 (V3 N개) 최대 250kW" 같은 요약 정보만 표시됩니다
  (supercharge.info가 실시간 사용 가능 여부를 제공하지 않기 때문 — 지어내지 않음).

## 알려진 한계

- 테슬라 슈퍼차저는 실시간 상태(사용 가능/충전 중)를 알 수 없습니다.
- 테슬라 슈퍼차저의 도시/도로명은 영어로만 제공됩니다 (`supercharge.info`가
  전 세계 데이터를 영어로만 관리 — 자동번역은 주소 오역 위험이 있어 도입하지
  않았습니다. "South Korea" 중복 표기만 제거했습니다).
- 지역 로테이션 특성상, 특정 지역의 신규/폐쇄 충전소 반영이 최대 6일까지
  늦어질 수 있습니다 (그 지역 차례가 돌아와야 반영).
